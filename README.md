## 产品简介

**NetPilot eNSP AI 网络助手**（仓库名：`netpilot-ai`）是面向华为 eNSP 实验环境的智能网络助手，基于开源项目 **eNSP AI Assistant** 二次开发而来。  
它可以理解你的自然语言配置意图，自动生成华为 VRP 配置命令，完成设备自动发现、连接、批量下发、拓扑发现和故障诊断，并通过 Streamlit Web 界面提供可视化交互。

典型使用场景：

- 网络课程 / 实验室：快速搭建、修改 eNSP 拓扑配置。
- 日常练习：用自然语言驱动 VRP 配置，减少命令记忆成本。
- 批量运维：一键扫描发现本机 eNSP 设备，读取主机名自动命名，批量下发与巡检。
- 故障排查：自动采集多设备信息，让 AI 辅助分析根因并给出修复建议。

## 核心特性

- **自然语言 → 配置任务**  
  输入一句话描述你的需求（例如"在 R1 和 R2 之间配置 OSPF，并在 R1 上创建 VLAN 10"），AI 自动解析为结构化任务清单，包含目标设备、动作类型与关键参数。
- **命令预览 + 逐条注释**  
  解析结果同时以两种视图展示：**结构化 JSON** 和 **对应的华为 VRP 配置命令**（带中文注释），执行前即可核对将要下发的配置；支持一键下载命令脚本。
- **AI 配置命令生成**
  - 常见场景（接口配置、OSPF、静态路由、VLAN、ACL、查询命令）内置命令模板，稳定可复现。
  - 复杂或未知操作回退调用大模型生成华为 VRP 命令序列。
- **端口扫描自动发现设备**
  - 自定义扫描 IP 与端口范围（默认 `127.0.0.1:2000-2100`），两阶段并发探测。
  - 通过"TCP 探测 + 提示符校验"两步区分真实 eNSP 设备与普通服务端口。
  - 自动读取设备 `sysname` / 型号 / 版本，并**用主机名命名设备**；未取到主机名时按前缀+序号回退命名。
- **设备名智能解析**  
  指令中写 `R1` 而实际设备名为 `OSPF-Core1` 也能自动匹配（精确 → 忽略大小写 → 主机名 → 数字序号启发式），避免"设备不存在"导致下发失败。
- **自动下发与执行结果反馈**
  - 从"待执行任务清单"中选择解析结果，一键下发到相关设备。
  - 按设备分组展示每个任务的命令、成功/失败状态与错误原因。
  - 未匹配到设备的任务会单独提示，不会被静默丢弃。
- **多设备远程命令执行**  
  选择多个已连接设备，一次性并发执行多条操作/查询命令，分设备展示每条命令回显。
- **设备配置读取与备份**  
  一键读取设备 `display current-configuration` 完整配置（自动处理 `---- More ----` 分页），支持保存为带时间戳的 `.cfg` 备份文件。
- **拓扑信息采集与拓扑构建**
  - 自动对多台设备执行关键信息采集命令（接口、IP、ARP、MAC、LLDP、sysname 等）。
  - 发现前自动检查并尝试启用各设备的 LLDP 功能，提升链路识别准确度。
  - 基于采集结果构建 NetworkX 拓扑图，推断设备间链路；支持保存 / 加载拓扑 JSON。
- **拓扑可视化**  
  基于 Matplotlib + Streamlit 渲染拓扑：以"设备键 (主机名)"标注节点，显示链路两端端口号（如 `GE0/0/1 <-> GE0/0/2`）。
- **故障诊断与修复建议**  
  输入故障现象描述（例如"R1 无法 ping 通 R2，但是接口状态是 UP"），系统并发采集每台设备的路由表与接口状态，由 AI 给出诊断分析、风险等级和修复建议命令。
- **健壮的 eNSP 会话处理**
  - 配置命令统一走逐条 timing 下发，不依赖提示符正则匹配。
  - 自动处理分页暂停（`---- More ----`）与配置模式残留，执行前后恢复会话状态。
  - 回显统一清洗（去除分页提示、ANSI 控制序列、命令回显与提示符）。
- **数据持久化与日志**  
  使用 SQLite 持久化设备列表（含主机名/型号/版本，兼容旧库自动迁移）；操作与错误记录到日志文件。

## 项目结构

- `src/`：核心逻辑（AI、连接、拓扑、执行、验证等）。
- `config/`：配置文件（`config.yaml`）与 AI 提示词模板（`prompts/`）。
- `data/`：数据库、日志、配置备份与拓扑文件（运行期自动生成）。
- `docs/`：产品说明与架构文档（含 `CHANGELOG.md` 修订说明与新增功能清单）。
- `tests/`：离线测试套件（无需真实设备与网络）。

## 架构总览

整体架构与模块划分可参考 `docs/ARCHITECTURE.md`，核心包括：

- **UI 层**（Streamlit）：负责交互与页面，四大标签页。
- **连接层**（`DeviceManager` + `SessionPool`）：设备发现、身份识别、连接、会话恢复与命令执行。
- **AI 层**（`LLMClient` / `IntentParser` / `CommandGenerator` / `FaultDiagnosis`）：意图解析、命令生成与故障诊断。
- **拓扑层**（`InfoCollector` / `TopologyBuilder` / `visualizer`）：拓扑采集、构建与可视化。
- **执行与验证层**（`ConfigExecutor` / `Tester` / `Reporter` / `TaskScheduler`）：配置下发、测试验证与报告生成。
- **基础设施层**（`DatabaseManager` / `logger` / `prompt_loader` / `CLIParser`）：存储、日志、提示词与 CLI 解析。

## 快速开始

### 1. 环境要求

- Python 3.10+（推荐 3.11 / 3.12 / 3.13）
- 华为 eNSP（含可运行的虚拟设备，并已开启串口/Telnet 端口映射）
- 可访问 DeepSeek 官方接口（或任意 OpenAI 兼容服务）

### 2. 安装依赖

```bash
git clone https://github.com/<你的用户名>/netpilot-ai.git
cd netpilot-ai
pip install -r requirements.txt
```

### 3. 配置大模型

项目**默认使用 DeepSeek**。复制 `.env.example` 为 `.env` 并填入 API Key：

```bash
cp .env.example .env
# 编辑 .env，设置：DEEPSEEK_API_KEY=sk-xxxxxxxx
```

> **`.env` 是可选的（非必需）**：不配置 `.env` 项目同样能正常启动运行，
> 只是 **AI 相关功能（自然语言指令解析、故障诊断、LLM 生成命令）不可用**；
> 此时设备扫描/连接、手动命令下发、批量命令执行、配置读取、拓扑自动发现等功能仍可正常使用。
> 页面顶部会给出醒目的配置引导。配置好 `.env` 后重启应用即可启用 AI。

默认参数（可在 `config/config.yaml` 的 `llm` 段调整，或在 Web 侧边栏临时切换）：

| 配置项           | 默认值                        |
| ------------- | -------------------------- |
| `provider`    | `deepseek`                 |
| `model`       | `deepseek-chat`            |
| `base_url`    | `https://api.deepseek.com` |
| `api_key_env` | `DEEPSEEK_API_KEY`         |

支持的 provider：`deepseek`（默认）、`openai`、`openai_compatible`（需填 `base_url`）、`local`（本地 Ollama）。
其中 `local`（Ollama）不需要 API Key。

### 4. 启动应用

```bash
streamlit run src/main.py
```

浏览器打开 <http://localhost:8501> 。

> **首次运行无需手动创建 `data/` 目录**：程序启动时会自动创建 `data/` 及其子目录
> （数据库、日志、配置备份、拓扑文件都生成在这里）。`data/` 属于运行期数据，
> 已通过 `.gitignore` 排除，仓库中仅保留一个占位文件 `data/.gitkeep` 以维持目录结构。

## 使用说明

启动后，左侧为**设备管理**侧边栏，主区域为四个标签页。

### 第一步：添加设备（推荐自动扫描）

侧边栏 →「🔍 扫描添加设备（自动发现）」：

1. 设置**扫描 IP**（本机 eNSP 一般为 `127.0.0.1`）。
2. 设置**起始 / 结束端口**（默认 `2000` / `2100`，覆盖 eNSP 默认映射范围）。
3. 勾选「用设备主机名命名（推荐）」，可设置未取到主机名时的**命名前缀**（默认 `R`）。
4. 点击「🚀 开始扫描」，等待结果。
5. 在结果中勾选要添加的设备（显示端口、主机名、型号），点击「➕ 添加所选设备」。

> 也可在「✍️ 手动添加」中自行填写设备名、IP 与 Telnet 端口。

### 第二步：连接设备

- 展开某台设备卡片，点击「🔗 连接」建立会话。
- 或点击「🔄 读取信息并重命名」，批量连接并读取主机名/型号/版本后自动重命名。
- 或点击「🔌 连接全部」，一次性连接所有设备。

### 第三步：自然语言指令解析与执行（标签页 1「💬 指令解析与执行」）

1. 在文本框中输入配置需求，例如：
   - `在 R1 和 R2 之间配置 OSPF`
   - `给 R2 的 GigabitEthernet0/0/0 配置 IP 10.0.0.1/24`
   - `在 R1 上创建 VLAN 10，并配置接口描述为 OFFICE`
2. 点击「🚀 开始解析」，等待 AI 返回任务清单。
3. 在「当前解析结果」中切换展示方式：
   - **📋 结构化 + 命令预览**（默认）：每个任务一张卡片，左栏为结构化 JSON 与设备匹配状态，右栏为**带中文注释的华为 VRP 命令**，可展开逐条注释。
   - **🧾 仅 JSON**：只查看原始结构化结果。
   - 下方「🧩 全部任务的命令汇总」可下载 `.txt` 命令脚本。
4. 确认无误后点击「💾 保存至待执行清单」。
5. 切换到标签页 3「⚙️ 手动配置下发」，在「待执行任务清单」中选中该任务，点击「🚀 立即执行该任务」，在「📊 执行结果反馈」中按设备查看结果。

### 第四步：手动与批量命令（标签页 3「⚙️ 手动配置下发」）

- **📝 手动 CLI 命令下发**：选择设备，逐行输入 VRP 命令，点击「📤 发送配置」。
- **📡 多设备远程命令执行**：勾选多个已连接设备，输入多条查询/操作命令（每行一条），点击「▶️ 执行远程命令」，按设备查看回显。
- **📥 设备配置读取与备份**：选择设备 →「📑 读取当前配置」（未连接会自动连接）→「💾 保存配置到服务器」，备份至 `data/config_backups/`。

### 第五步：拓扑自动发现（标签页 2「🗺️ 拓扑自动发现」）

1. 勾选参与发现的设备，按需确认两个选项：
   - **「强制重新发现（忽略历史旧拓扑）」**（默认开启）：发现前清空旧图，避免残留上一次实验的拓扑；
   - **「等待 LLDP 收敛后再采集（推荐）」**（默认开启）：等 LLDP 邻居表稳定后再采集，避免首次发现链路不完整。
2. 点击「🚀 开始拓扑发现」。系统会自动启用 LLDP、并发采集信息并构建拓扑。
3. 下方「📍 当前拓扑视图」展示节点与链路。
4. 切换实验后若希望彻底重来，点击「🧹 清空当前拓扑」清除内存与 `data/topology.json`。

### 第六步：网络故障分析（标签页 4「🔍 故障分析排错」）

1. 详细描述故障现象（设备名、方向、是否 ping 通、接口状态等）。
2. 点击「🩺 开始 AI 诊断」。
3. 查看诊断分析报告、风险等级与修复建议命令。

## 运行测试

项目内置离线测试套件，**不依赖真实设备与网络**。测试分两套风格：

**① pytest 风格**（用 `pytest` 收集，共 44 个用例）：

```bash
pytest tests/                            # 一次性运行全部 pytest 用例
# 也可单独运行：
pytest tests/test_vrp_commands.py        # 华为 VRP 命令正确性（Trunk/Access/SVI/OSPF/路由）

pytest tests/test_topology_refresh.py    # 拓扑刷新与 LLDP 收敛
```

**② 脚本风格**（用 `python` 逐个运行，共 100 项断言）：


> 说明：`pytest tests/` 收集的是 pytest 风格的 44 个用例；脚本风格的 6 个文件需用
> `python tests/xxx.py` 单独运行——两种方式合计 **144 个测试单元**，全部通过。

## 常见问题

| 现象            | 排查方向                                                          |
| ------------- | ------------------------------------------------------------- |
| 扫描无结果         | 确认 eNSP 设备已启动、已开启端口映射；确认扫描 IP / 端口范围与 eNSP 映射一致               |
| 连接失败          | 检查设备是否已启动、Serial Port 端口号是否正确、是否被其他程序占用                       |
| 解析结果为空        | 检查 `.env` 中 `DEEPSEEK_API_KEY` 是否有效、网络是否可达 `api.deepseek.com` |
| 执行提示"未找到目标设备" | 指令中的设备名与设备列表不一致；可用「🔄 读取信息并重命名」统一命名，或依赖名称智能解析                 |
| 读取配置为空        | 会话可能停留在分页或配置模式；点击该设备「🔄 读取此设备信息」重建会话后重试                       |
| 拓扑无链路         | 确认设备已启用 LLDP，稍等邻居收敛后再次发现                                      |
| 启动报错 `File not found: data/app.log` | 旧版本的问题；新版会自动创建 `data/` 目录。若仍报错，请确认工作目录为项目根目录（`cd` 到含 `src/` 的目录再运行） |
| 下载后 `data/` 目录不存在 | 属正常现象：`data/` 是运行期数据，不入库；首次运行会自动生成 |
| 未配置 `.env` 能否使用 | 可以。应用正常启动，仅 AI 功能（指令解析/故障诊断）不可用，其余功能正常；页面顶部会提示如何配置 |
| 提示"AI 功能当前不可用" | 未检测到大模型 API Key；按提示复制 `.env.example` 为 `.env` 并填写 `DEEPSEEK_API_KEY`，重启应用即可 |

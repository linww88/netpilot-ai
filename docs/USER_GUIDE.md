## 典型使用流程

本文档面向使用者，按操作顺序说明如何在 eNSP 实验环境中使用本工具。

---

### 1. 环境准备

1. 安装 Python 依赖：
   ```bash
   pip install -r requirements.txt
   ```

2. 在 eNSP 中创建好虚拟拓扑，**启动所有设备**，并确认已开启串口/Telnet 端口映射
   （eNSP 默认从 `2000` 端口开始依次映射，可在设备 `Serial Port` 设置中查看）。

3. 配置大模型。项目**默认使用 DeepSeek**，在项目根目录创建 `.env`：
   ```bash
   cp .env.example .env
   # 编辑 .env，填入：DEEPSEEK_API_KEY=sk-xxxxxxxx
   ```
   如需改用其他服务，可修改 `config/config.yaml` 的 `llm` 段（`provider` / `model` / `base_url` / `api_key_env`），
   或直接在 Web 侧边栏「🤖 AI & 搜索配置」中临时切换。

4. 启动 Web 应用：
   ```bash
   streamlit run src/main.py
   ```
   浏览器访问 http://localhost:8501

5. 自检（可选）：若想确认 API Key 可用，运行
   ```bash
   python tests/test_deepseek.py
   ```

---

### 2. 添加设备

推荐使用**自动扫描**，避免手工核对端口号。

#### 2.1 自动扫描添加（推荐）

侧边栏 →「🔍 扫描添加设备（自动发现）」：

1. **扫描 IP**：本机 eNSP 一般为 `127.0.0.1`。
2. **起始 / 结束端口**：默认 `2000` – `2100`，覆盖 eNSP 默认映射范围；可通过 `config/config.yaml` 的
   `connection.scan_start_port` / `scan_end_port` 修改默认值。
3. **用设备主机名命名（推荐）**：勾选后，系统读取设备 `sysname` 作为设备名。
4. **命名前缀**：未能取到主机名时的回退前缀（默认 `R`，将依次生成 `R1`、`R2`……）。
5. 点击「🚀 开始扫描」。

扫描完成后：

- 顶部提示开放端口总数与识别出的设备数量；
- **未识别为设备的端口**会单独列出（例如其他本地服务占用）；
- 识别出的设备以多选框列出（显示 `端口 · 主机名 · 型号`），勾选后点击「➕ 添加所选设备」。

> 命名优先级：**真实主机名 → 前缀+序号 → 前缀+端口**，保证设备名唯一。
> 已存在的设备会自动跳过，不会重复添加。

#### 2.2 手动添加

侧边栏 →「✍️ 手动添加」：

1. 填写**设备名**（如 `R1`）、**IP 地址**（`127.0.0.1`）、**Telnet 端口**（如 `2000`）。
2. 点击「➕ 添加设备」，设备会同时写入内存与 SQLite 数据库。

---

### 3. 建立连接

侧边栏「📋 已添加设备」区域：

- **连接全部**：点击「🔌 连接全部」，一次性连接所有设备。
- **批量读信息并重命名**：点击「🔄 读取信息并重命名」，批量连接并读取主机名/型号/版本，
  若读到的 `sysname` 与当前设备名不同，会自动重命名并同步数据库。
- **单台连接**：展开设备卡片 →「🔗 连接」。
- **单台刷新**：展开设备卡片 →「🔄 读取此设备信息」。

设备卡片标题会显示连接状态（🟢 已连接 / 🔴 未连接）与型号；展开后可见类型、地址、主机名与版本。

> 提示：连接失败时请检查 eNSP 设备是否已启动、`Serial Port` 端口号是否正确、端口是否被占用。

---

### 4. 自然语言指令解析

切换到标签页「💬 指令解析与执行」。

#### 4.1 输入指令

在文本框中用中文描述需求，例如：

| 意图 | 示例指令 |
| --- | --- |
| 接口 IP | `给 R2 的 GigabitEthernet0/0/0 配置 IP 10.0.0.1/24` |
| OSPF | `在 R1 和 R2 之间配置 OSPF` |
| 静态路由 | `在 R1 上配置到 192.168.2.0/24 的静态路由，下一跳 10.0.0.2` |
| VLAN | `在 R1 上创建 VLAN 10，并配置接口描述为 OFFICE` |
| 查询 | `查看 R1 的路由表` |
| 组合 | `在 R1 和 R2 之间配置 OSPF，并在 R1 上创建 VLAN 10` |

点击「🚀 开始解析」，等待 AI 返回任务清单。

> 说明：解析会**调用大模型**（默认 DeepSeek）。大模型只负责把中文意图翻译为结构化任务，
> 其余命令生成与 JSON 清洗均在本地完成。

#### 4.2 查看解析结果（双视图）

解析结果提供两种展示方式，通过顶部「展示方式」切换：

**📋 结构化 + 命令预览（默认）**

每个任务一张卡片，标题形如 `任务 1｜R1｜config_ospf`，内容分左右两栏：

- **左栏**
  - 🖥️ 目标设备：显示指令中的设备名，以及匹配状态徽标
    （`已匹配设备：OSPF-Core1` 或 `⚠️ 未找到该设备`）；
  - 🧾 结构化 JSON：任务的目标设备、动作类型与参数。
- **右栏**
  - ⌨️ **对应华为 VRP 配置命令**：按 `序号. 命令    # 注释` 逐行列出；
  - 📖 可展开「命令逐条注释」查看每条命令的中文说明。

示例：

```
任务 1｜R1｜config_ospf
  1. system-view   # 进入系统视图（配置模式）
  2. ospf 1        # 启动 OSPF 进程 1
  3. quit          # 退出至用户视图
```

**🧾 仅 JSON**

只显示原始结构化任务列表，适合需要复制 JSON 的场景。

> 「命令预览」由本地规则生成（基于命令语义与任务参数），**不会额外消耗大模型额度**。

#### 4.3 命令汇总与下载

展开「🧩 全部任务的命令汇总」，可看到按任务分段汇总的全部命令（含注释），
并点击「⬇️ 下载命令脚本（.txt）」保存为文本文件，便于人工复核或离线备份。

---

### 5. 执行任务

1. 在解析结果下方点击「💾 保存至待执行清单」。
2. 切换到标签页「⚙️ 手动配置下发」。
3. 在「📋 待执行任务清单」下拉框中选中刚保存的任务。
   - 下拉项显示为 `[时间] 原始指令`，下方展示该任务的 JSON。
4. 点击「🚀 立即执行该任务」。
   - 若指令中的设备名未在设备列表中找到，会先给出警告提示，相关任务将无法执行。
   - 执行时系统会自动把指令中的设备名解析为真实设备键
     （例如 `R1` → `OSPF-Core1`）。
5. 在「📊 执行结果反馈」中查看结果：
   - 未匹配设备的任务会单独以错误区列出；
   - 每台设备一个可展开面板，显示 ✅/❌、任务描述、命令列表与错误原因；
   - 「🧾 原始执行结果 (JSON)」可展开查看完整数据。
6. 点击「🧹 清除执行记录」可清空结果展示。

---

### 6. 手动命令下发与多设备并发

同样是标签页「⚙️ 手动配置下发」。

#### 6.1 手动 CLI 命令下发

1. 在「🎯 选择目标设备」中选择设备。
2. 在文本框中输入多行 VRP 命令（每行一条），例如：
   ```
   system-view
   vlan 20
   description TEST
   quit
   quit
   ```
3. 点击「📤 发送配置」，查看成功/失败提示。

#### 6.2 多设备远程命令执行

1. 在设备多选框中勾选多个**已连接**设备（默认全选）。
2. 输入一组操作/查询命令（每行一条），例如：
   ```
   display ip interface brief
   display ip routing-table
   ```
3. 点击「▶️ 执行远程命令」，系统并发执行。
4. 在「📃 多设备命令执行结果」中，按设备展开查看每条命令的完整回显。

---

### 7. 设备配置读取与备份

标签页「⚙️ 手动配置下发」→「📥 设备配置读取与备份」：

1. 选择要读取的设备。
2. 点击「📑 读取当前配置」：
   - 若该设备尚未连接，会自动尝试连接；
   - 读取 `display current-configuration` 完整回显（内部自动处理 `---- More ----` 分页），
     成功后提示读取字符数。
3. 「📄 最近读取的设备配置」区域展示配置内容。
4. 点击「💾 保存配置到服务器」，将配置保存为
   `data/config_backups/<设备名>_config_<时间戳>.cfg`。

> 若读取失败：先点击侧边栏该设备的「🔄 读取此设备信息」重建会话，再重试。

---

### 8. 拓扑自动发现与可视化

切换到标签页「🗺️ 拓扑自动发现」：

1. 在「选择参与拓扑发现的设备」中勾选设备（默认全选）。
2. 按需设置两个选项（默认均已开启）：
   - **「强制重新发现（忽略历史旧拓扑）」**：发现前先清空内存中的旧图，
     即使本次采集失败也不会残留上一次实验的拓扑；
   - **「等待 LLDP 收敛后再采集（推荐）」**：正式采集前轮询 LLDP 邻居表，
     待各设备邻居行数连续两轮稳定后再采集，避免首次发现不完整
     （设备刚启动时邻居表需要几秒才填充完整，若立即采集会得到空链路）。
3. 点击「🚀 开始拓扑发现」。系统会依次：
   - 检查未连接设备并尝试自动连接；
   - 为各设备检查并尝试启用 LLDP（失败会单独提示）；
   - 等待 LLDP 邻居信息收敛（如已开启该选项）；
   - 并发采集接口、IP、ARP、MAC、LLDP、sysname 等信息；
   - 构建 NetworkX 拓扑图并持久化为 `data/topology.json`。
4. 完成后提示识别到的设备数与链路数；若有已选设备未出现在拓扑中，会单独列出。
5. 「📍 当前拓扑视图」展示拓扑图：节点标注为「设备键 (主机名)」，边显示两端端口。

> **关于「当前拓扑视图」的两种状态**
> - 若本次会话**尚未成功执行过**发现，但图中仍有节点，页面会显示醒目警告
>   「⚠️ 当前展示的是**历史保存的拓扑**（可能是上一次实验的残留）」——此时请点击
>   「🚀 开始拓扑发现」重新发现，或点击「🧹 清空当前拓扑」后重试。
> - 若本次已成功发现，则显示「本次发现：N 台设备、M 条链路」。

> **切换实验后拓扑没刷新？** 点击「🧹 清空当前拓扑」按钮，可清除内存图并删除
> `data/topology.json`；下次发现即为全新拓扑。只要保持「强制重新发现」开启，
> 每次发现都会以实时采集结果为准，不会残留旧实验数据。

> 若识别到 0 条链路：确认各设备已启用 LLDP，并保持「等待 LLDP 收敛」开启后再次点击发现。

### 9. 网络故障分析与修复建议

切换到标签页「🔍 故障分析排错」：

1. 在「⚠️ 故障现象描述」中尽量详细描述，例如：
   > `R1 无法 ping 通 R2，但是 R1 接口状态是 UP，R2 侧看不到任何 ARP 表项`
2. 点击「🩺 开始 AI 诊断」。系统会：
   - 并发采集所有设备的 `display ip routing-table` 与 `display ip interface brief`；
   - 调用 AI 结合采集数据与你的描述进行分析。
3. 页面展示「🔬 诊断分析报告」：
   - 分析详情；
   - 风险等级（如 `Medium`）；
   - 「🛠️ 修复建议命令」列表，可复制后到「手动 CLI 命令下发」中执行验证。

### 10. 常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| 扫描不到设备 | 确认 eNSP 设备已启动并开启端口映射；核对扫描 IP 与端口范围 |
| 连接失败 | 检查设备是否启动、`Serial Port` 端口号、端口是否被占用 |
| 扫描把普通服务识别为设备 | 系统已用「提示符校验」过滤，如仍误判可在结果中取消勾选该端口 |
| 解析结果为空 | 检查 `.env` 的 `DEEPSEEK_API_KEY`、网络可达性与侧边栏模型配置 |
| 执行提示"未找到目标设备" | 指令中的设备名与设备列表不一致，使用「🔄 读取信息并重命名」统一，或依赖名称智能解析 |
| 读取配置为空 | 会话可能停留在分页/配置模式，刷新该设备会话后重试 |
| 拓扑无链路 | 确认 LLDP 已启用、邻居已收敛，再次执行发现 |
| 命令下发超时 | 确认设备未卡在分页暂停；系统会在执行前后自动恢复会话状态 |
